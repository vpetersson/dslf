Your links,
on your own box.

Damn Small Link Forwarder is a self-hosted link shortener and link-index page. The configuration is a CSV file. There is no database, no dashboard and no account, because a redirect does not need any of them.

Quick start

The image ships with example config, so it runs before you have written anything. 

# Run it with your own redirects mounted in
docker run -p 3000:3000 \
  -v $(pwd)/redirects.csv:/app/redirects.csv \
  ghcr.io/vpetersson/dslf:latest

  1. Write a CSV

    One row per link: the path, where it goes, and 301 or 302.

  2. Mount it

    Mount the file at runtime, or bake it into an image with the example Dockerfile.

  3. Point a domain at it

    Any host that can run a container will do. It is one process and one port.

Two files, both optional to learn

redirects.csv is the only file you need. Add link-index.yaml if you also want a link-index page at the root, themed with Catppuccin. 

# link-index.yaml
profile:
  name: "Your Name"
  bio: "Short line about you"

theme:
  preset: mocha        # mocha | macchiato | frappe | latte
  buttonStyle: glass   # glass | solid | outline

Both files can be mounted at runtime, so changing a link is a file edit and a restart, not a deploy.

What you get

Real redirects

Proper 301 and 302 responses with a Location header, so curl, scripts and link checkers follow them the way browsers do.

No database

Configuration is a CSV and a YAML file. Nothing to migrate, back up, or wake at 3am for.

No tracking

No analytics, no cookies, no third-party requests. Visitors are redirected and that is the end of it.

Link-index page

An optional landing page in place of a hosted link-in-bio service, themed with Catppuccin.

Import what you have

Pull existing short links out of Rebrandly with one command.

Published with an SBOM

Each release publishes a software bill of materials, so what is inside the image is a matter of record.
